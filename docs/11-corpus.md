# corpus.py 详解 —— 解析评测语料(50 训练 + 15 泛化)

## 这个文件为什么存在

`benchmark_llm.py` 要回答"解析器到底准不准",得有**带标准答案的评测数据**。这个文件就是标注语料:每条 = 一句任务文本 + 期望解析结果。

## 结构:训练集与泛化集刻意分离

### `ENTRIES`(50 条)—— 训练语料

覆盖规则解析器能处理的主要表达:银行办卡/取钱、接孩子放学、买菜、取快递、开会、自习、看病、打疫苗、健身房、食堂……每个场景都标注了完整的期望字段:

```python
{"text": "明天上午9点去银行办卡",
 "day": 1, "earliest": 540, "latest": 720, "fixed": None,
 "deadline": None, "priority": 2, "duration": 30, "place": "银行"}
```

时间字段约定为"**当天第几分钟**"(0-1439),评测脚本 `benchmark_llm.py` 会把 `day × 1440` 加上变成绝对分钟,和解析器输出口径一致——避免"明天上午9点"解析出 1980、语料写 540 这种对不上。

### `GEN_ENTRIES`(15 条)—— 泛化集

**故意放进规则解析器处理不了的表达**:
- "今晚/明晚"——规则没有"今晚"这种词;
- "药房/菜鸟驿站/游泳馆/书店/饭店"——新地点词,规则词典里没有;
- "接娃"——固定动词列表外的说法;
- "晚上12点"——边界时间。

设计意图:规则解析器"背"过 50 条语料(它的正则就是按语料写的),泛化集测的是**没见过的新表达**,这才能量出 LLM 的"泛化能力"而不是"背题能力"。benchmark_llm.py 里对泛化集的通过率阈值(≥4/15)比训练集(≥35/50)低,就是这个道理——泛化本来就难。

## 使用方式

```bash
python benchmark_llm.py --rule        # 规则解析:训练 50 + 泛化 15
python benchmark_llm.py --gen         # LLM 泛化集(需配 Key)
python benchmark_llm.py --limit 10    # 只跑前 10 条调试
```

## 局限(如实说)

50+15 条是**作者手工编写**的语料,不是真实用户采集:
- 覆盖面有限,"背题风险"存在于训练集(规则/LLM 都可能过拟合语料格式);
- 泛化集 15 条样本量小,结论只能当参考。

要提升说服力,下一步是采集真实用户输入 + 人工标注,扩到几百条——这也是项目往 AI 方向走的数据基础。
