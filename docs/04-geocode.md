# geocode.py 详解 —— 地址/关键词 → 经纬度

## 这个文件为什么存在

解析器给出的是地点**关键词**("银行""学校""超市"),求解器需要的是**经纬度**。这个文件负责把文本变成坐标,核心服务是高德地图的 Web 服务 API:

- 结构化地址 → 坐标(地理编码 `geocode`)
- 关键词 → POI(兴趣点搜索 `place/text`)
- 中心点附近 → POI(`place/around`,处理"去附近饭店")

## 设计原则

1. **失败永远返回 None / 空列表,绝不抛异常**:网络抖动、Key 失效、返回垃圾数据都吞掉,上层(解析流程)自然降级。
2. **只缓存成功结果**:失败的请求不缓存,下次重试——避免 Key 恢复后还一直用旧缓存。
3. **内存缓存 + 简单 key**:模块级 `_CACHE` 字典,key 是"关键词+城市"或"关键词+中心坐标"。不需要 Redis,单用户工具够用,进程重启即清空,不怕脏数据。

## 重点函数逐个说明

### `_auto_city(address)` —— 自动判断搜索城市

地址里带"省/市/区县"就全国搜(返回 None 表示不限定城市),否则用默认城市(池州)。这样"上海市浦东新区"能命中,而"银行"这种泛词在本地城市命中率更高。

### `_valid_location(lng, lat)` —— 过滤无效坐标

高德偶尔返回 `(0,0)` 或接近 0 的坐标,直接过滤,防止把"家"定位到大西洋。

### `_split_address(address)` —— 拆省市前缀

"安徽省池州市贵池区远东国际花园" → 拆出城市"池州市" + 核心词"远东国际花园",用核心词在指定城市搜,而不是拿整串长地址去匹配 POI。

### `geocode_address(address, city)` —— 精确地理编码

结构化地址(有门牌/小区名)→ 经纬度 + 格式化地址。city 为 None 时由 `_auto_city` 自动判断。

### `_poi_query(keyword, city)` —— POI 文本搜索(带缓存)

返回第一个 POI `(lng, lat, 名称)`。`offset=1` 只取一条(主流程只需要一个坐标,候选列表走 `search_candidates`)。

### `search_nearby(keyword, center, radius=3000)` —— "附近"搜索

处理"去附近饭店吃饭":以家为中心搜 3 公里内的饭店。这是主流程里泛词(比如只写"超市")的兜底手段。

### `_haversine_m(lat1, lng1, lat2, lng2)` —— 两点直线距离(米)

全市搜索结果没有高德返回的 `distance` 字段,用 Haversine 公式按经纬度估算直线距离,只用于候选排序(排后面),不参与路径规划(路径规划走真实路网)。

### `_text_search_multi(keyword, city, offset=8)` —— 全市文本搜索(多候选)

`place/text` 接口 + `citylimit="true"`,限定在默认城市内搜多个 POI,带缓存,失败返回空列表。给"去偏远地方办事"兜底:附近搜不到不代表这个城市没有,只是不在附近。

### `search_candidates(keyword, center, limit=8, radius=20000)` —— 多候选按距离排序

先搜 center 周边 `radius` 米内(默认 20km,覆盖同城大部分范围),按距离升序返回 `{name, address, lat, lng, distance_m}`。近处凑不满 `limit` 个时,自动补一次全市文本搜索(`_text_search_multi`),让"去偏远地方办事"也能找到候选——远处的地点按 `_haversine_m` 估算距离排后面,仍可被用户选中。全部结果去重。

用途是前端**让用户自己选**,而不是程序自动代选——地点有歧义时,把选择权交还用户是产品设计上的自觉(见 `app.py` 的 `need_pick` 流程)。

### `search_poi(keyword, city)` —— 多级兜底搜索

搜索顺序设计得很细:
1. 拆出城市+核心词 → 在指定城市搜;
2. 没搜到 → 核心词全国搜(兜底外地地标,如"陆家嘴");
3. 整词在默认城市搜;
4. 还没搜到 → 整词全国搜。
四级逐步放宽,最大化命中率。

### `resolve_address(address)` —— 定位"家"

先精确地理编码,失败再用 POI 搜索兜底。返回 `(lng, lat, 显示名, 来源)` 四元组,来源字段让前端知道"这是精确定位还是模糊搜索",用于提示用户微调。

### `extract_keyword(text)` —— 任务文本 → 地点关键词

简化版 NLP:把动作词/时间词(办卡、取快递、买菜、去、到、上午、下午、明天...)从文本里删掉,剩下的就是地点关键词。规则是长列表正则删除,粗暴但有效,是 `fill_missing_coords` 的兜底来源。

### `fill_missing_coords(tasks)` —— 批量补坐标

给没有坐标的任务调 `search_poi` 补坐标,优先用解析出的地点类型(如"银行"),再用提取的关键词。返回补了几个,`app.py` 把这个数字回给前端显示("已自动补全 3 个地点坐标")。

## 与前端候选选择的关系

`search_candidates` + `db.search_places`(地点记忆)共同组成 `app.py` 的候选列表:去过的地点排最前标"常用",高德搜索结果排后面标"搜索",用户点选后带着 `places` 参数重发请求,流程在 `app.py` 的 `/api/plan` 里闭环。
