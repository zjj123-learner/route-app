# route.py 详解 —— 高德真实路网时间矩阵

## 这个文件为什么存在

上一版优化器用"直线距离 × 估算速度"算路程时间,误差大(直线 2 公里,实际绕路可能 5 公里)。这个文件调高德**路径规划** Web 服务(步行/驾车),拿到真实路网的距离和时间,并附带轨迹点(polyline)供前端画路线。

## 设计原则:一个规划只用一张矩阵

优化器每次评价一个顺序都要查"任意两点之间要多久",如果每次现查 API,一次排序要打几十上百个请求。所以 `app.py` 里先调 `build_matrix` 把**所有要去的点两两算一遍**,存成字典,三个求解器(启发式/退火/遗传)共用同一张表——高德请求不翻倍。

## 重点函数逐个说明

### `_haversine_km(a, b)` + `_straight(mode, a, b)`

直线距离兜底。`_straight` 返回 `(km, minutes, None, False)`——最后一个 `False` 是"非真实路网"标记,前端靠它显示"直线估算(已降级)"。

### `_pair_key(mode, a, b)` —— 请求去重键

坐标四舍五入到 5 位小数(约 1 米精度)作为缓存键。两个几乎相同的坐标(如两条任务都在家)只请求一次。

### `_parse_polyline(path)` —— 轨迹解析

高德每步返回 `lng,lat;lng,lat;...`,拼接成 `[(lat, lng), ...]` 点列表,相邻重复点去重;超过 300 点抽稀一半,免得前端画太多点卡顿。

### `_fetch_route(mode, a, b)` —— 单次路径规划

- **限速**:高德免费 Key 约 3 次/秒,两次请求间隔至少 0.35 秒(模块级 `_last_request` 记录上次时间);
- 失败返回 None,由上层换直线兜底。

### `_get_cached(mode, a, b)` —— 读缓存(核心)

缓存策略分两种:
- **成功结果长期缓存**:同一对点只请求一次,之后一直复用;
- **失败结果短时缓存(FAIL_TTL=60 秒)**:60 秒内不重试(避免 Key 失效时疯狂打请求),到期自动重试。降级是**临时**的,不是永久。

### `build_matrix(points, mode)` —— 建全矩阵

1. **坐标去重**:同一坐标只算一次(比如起点和"回家"任务),能少调一堆 API;
2. 两两求真实时间,`i == j`(自己到自己)直接填 0,不算请求;
3. 矩阵键是 `(la1, ln1, la2, ln2)` 四元组,**不带 mode**——一次规划只用一种出行方式,和 `optimizer.travel_minutes` 查表键保持一致;
4. 返回 `(matrix, real_ok, total)`:`real_ok` 是真实路网的有向对数(含缓存命中),前端显示"真实路网时间 12/20 对";全是 0 就显示"已自动降级直线估算"。

### `route_minutes(mode, a, b)` —— 单对查询

返回 `(km, minutes)`,给不需要轨迹的场景用。

## 为什么不直接用高德矩阵 API(一次给全)

高德 Web 服务没有"一键算 N 点全矩阵"的免费接口,只能两两调。所以这里自己管理矩阵 + 缓存 + 限速。免费配额下,10 个任务约 110 对请求(含去重),按 0.35s 限速约 40 秒——这也是为什么默认任务上限 30 个(`app.py` 校验)的原因之一。
