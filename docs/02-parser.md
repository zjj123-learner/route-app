# parser.py 详解 —— 规则式中文任务解析

## 这个文件为什么存在

用户输入是中文自然语言:"明天上午9点去银行办卡(重要)、下午3点去学校接孩子放学、晚上7点前从驿站取快递"。求解器需要的是结构化字段:`day`(第几天)、`earliest/latest/fixed/deadline`(四类时间约束)、`priority`、`duration`、`place`。

所以需要一个"翻译官"。这里选择**纯规则(正则 + 词典)**而不是 NLP 模型,原因:

1. **零依赖离线可用**:不需要任何第三方 NLP 库,`pip install` 一个包都不用多装,没有 Key 也能跑。
2. **毫秒级**:正则扫描,比调模型快几个数量级。
3. **行为确定、可测**:同样的输入永远同样的输出,`test.py` 里 50 条语料全部可断言。模型解析做不到这一点。
4. **作为基线**:LLM 解析(见 `llm_parser.py`)的对照基线,评测时"规则没调优"的定位很干净。

## 核心设计约定

### 时间统一成"当天第几分钟"

所有时间(`earliest/latest/fixed/deadline`)内部统一用**当天的分钟数**表示:0 = 00:00,540 = 09:00,900 = 15:00,1440 = 24:00。

好处:
- 避免 `datetime` 跨天/时区/字符串比较的坑,求"早到等多久、迟到罚多久"就是两个整数相减;
- 优化器的评价函数(`optimizer.evaluate_order`)完全不需要知道"这是几点",只做整数运算。

### 多日用"绝对分钟"解决跨天

任务可能落在不同天:"明天上午9点"(day=1)。如果时间永远按当天分钟算,比较"明天的 9 点"和"今天的 15 点"就会错。解法:`parse_line` 最后把所有时间字段加上 `day * 1440`,变成**绝对分钟**(第 1 天 09:00 = 540 + 1440 = 1980)。这样评价函数天然支持跨天排序,不用特殊处理。

### 四类时间约束的语义

| 字段 | 含义 | 示例 |
|---|---|---|
| `fixed` | 固定预约,不能迟到,迟到按分钟重罚 | 开会/接孩子/面试 |
| `earliest` + `latest` | 时间窗,早到要等、晚到要罚 | 上午 9 点到 12 点 |
| `deadline` | 截止时间,必须在这之前完成 | 晚上 7 点前取快递 |
| (无时间) | 自由安排 | 顺便去超市买菜 |

## 重点函数逐个说明

### `extract_day(text, today)` —— 日期 → 第几天

识别"今天/明天/后天/大后天"(词典匹配)、"周X/星期X"(按今天星期几算偏移,过期自动顺延到下周)、"X月X日"(按真实日期差)。没有日期 = 0。

### `cn_time_to_str(text)` + `cn_to_int(cn)` —— 中文数字转阿拉伯

把"上午九点半"先转成"上午9点30分",再用后面的 `TIME_RE` 统一解析。`cn_to_int` 处理"十/十二/二十"这类中文数字(十=10,十五=15,二十=20)。

### `parse_time_tokens(text)` —— 扫描所有时间点

- 用 `TIME_RE` 找出所有"几点几分";
- **12 小时制修正**:"下午/晚上/傍晚"的小时 +12,"凌晨 12 点"归 0,"中午 11 点前" +12;
- **前缀继承**:"下午3点到5点"里第二个"5点"没有前缀,继承上一个"下午",变成 17:00 而不是凌晨 5:00——这是中文口语最常见的坑,特意处理。

### `build_time(text, tokens)` —— 时间点 → 时间约束

按优先级判定:
1. 两个时间点之间是"到/至/-/~" → 起止时间窗;
2. 时间后面跟"前" → deadline;
3. 单个时间 + 固定动词(开会/接/面试/考试等 `FIXED_VERBS`) → fixed;
4. 单个时间 → earliest,并自动补 latest = earliest + 180(3 小时窗口)。

### `parse_line(line, today)` —— 解析一行任务(核心)

组装顺序很讲究:
1. 先提日期(`extract_day`),再转中文数字、扫时间;
2. 找地点(`find_place` 词典匹配:银行/超市/学校/快递驿站等);
3. 判优先级:"重要/必须/务必"= 3,"顺便/有空/不急"= 1,默认 2;
4. 定时长:开会/看病/上课 = 60 分钟,取快递/买菜/买药 = 20,其他默认 30;**写了明确起止时间段的用段长当时长**(9 点到 12 点 = 180);
5. 只有模糊时段(上午/下午)没具体时间 → 用 `vague_period` 的时段窗口;
6. 有日期没时间 → 默认当天的 6:00-24:00;
7. 最后所有时间抬成绝对分钟,输出任务字典。

### `parse_tasks(text, today)` —— 多行入口

按行切分,每行 `parse_line`,过滤空行。前端/CLI/测试都走这里。

## 常见坑与取舍

- **地点的 `place` 输出规范关键词,不要品牌名**:用户写"建设银行/工商银行"统一归到"银行",这样地理编码和地点记忆才能复用(`geocode.py` 里 `fill_missing_coords` 就靠这个关键词去搜)。
- **固定动词列表是白名单**:`FIXED_VERBS` 里特意**不放**"取快递/取件",因为取快递不是预约,误判成 fixed 会导致优化器为了"准时"付出巨大代价——这个坑在 `llm_parser.py` 里还专门写了兜底再修一次。
- **规则解析的边界**:没写到的表达(如"今晚"、新地点"游泳馆")识别不了,这正是引入 LLM 解析的理由,见下一份文档。
