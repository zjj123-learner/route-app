# app.py 详解 —— Flask 路由 + 全流程组装

## 这个文件为什么存在

这是整个系统的**编排层**:把解析(parser/llm_parser)、地理(geocode/route)、求解(optimizer/simanneal/genetic)、记忆(db)四部分串成一条流水线,对外暴露 HTTP API 给前端。它自己**不实现任何算法**,只负责组装和错误处理——这是分层设计的刻意选择:算法模块可以独立测试、独立复用(CLI、benchmark 都直接 import)。

## 主流程 `/api/plan`(POST)——一次请求的完整旅程

### 1. 参数解析
- 从 JSON 拿任务文本、出行方式(walk/drive,非法值回退 walk)、起点坐标;
- `parse_hhmm` 把 "08:30" 转成分钟数,解析失败默认 480(08:00)——用户输入垃圾不崩;
- buffer(每段路预留时间)限制 0~120,越界回退 0。

### 2. 解析任务
`parse_with_llm(text, prefer_llm=config.LLM_PARSER)`:配了 `LLM_PARSER=1` 优先 LLM,逐行失败回退规则。没解析出任务返回 400。

### 3. 地点确定(最复杂的部分,按优先级)
1. 用户在前一步选好的地点(`places` 参数)直接采用;
2. "家"用起点坐标,不靠 POI 猜;
3. "去附近XX"以家为中心搜周边;
4. 地点记忆(去过的地方)进候选列表;
5. 泛词(如"超市")以家为中心兜底搜一次;
6. 仍有多义地点 → 返回 `need_pick` 候选列表,前端展示让**用户自己选**,选完带 `places` 重发请求(两轮交互);
7. 坐标缺失且无法补全 → 400 提示"把地点说清楚"。

### 4. 锁定任务校验
前端传 `[{name, pos}]`,解析成 `{任务下标: 槽位}`;位置越界跳过、两个任务钉同一槽位返回 400。

### 5. 真实路网矩阵
`route.build_matrix(points, mode)` 一次算完所有两两路程,`route_info` 字符串告知前端"真实路网 12/20 对"或"已降级直线估算"。

### 6. 三个算法各跑一遍,取最优
```python
route_results = {
    "heuristic": optimize_route(...),
    "simanneal": sa_route(..., seed=20260826),
    "genetic":   ga_route(..., seed=20260826),
}
```
- 复用同一张路网矩阵,高德请求不翻倍;
- 固定 seed,结果可复现;
- 前端拿到 `all_routes`,可以切换看三条路线对比。

每个算法还额外测量两个指标,供前端"算法对比"可视化:
- `elapsed_ms`:墙钟耗时(`time.perf_counter` 包住求解调用);
- `evals`:评价次数——给 `options` 注入 `_counter={"n":0}`,由 `optimizer.evaluate_order` 每评估一个候选顺序 +1,量化"计算工作量"(暴力枚举 n 任务 = n! 次,退火 = 迭代次数,遗传 ≈ 种群×代数)。

两者与 `stats.total` 一起构成"耗时/工作量/成本"三指标对比,都是越小越好。

### 7. `_payload(rr)` —— 结果转前端结构
- `insert_base_stops` 插入回家休息停靠(按时段偏好);
- 生成 `stops`(含到达/离开时间)、`route_lines`(每段轨迹 polyline,历史计划没有轨迹所以前端画直连虚线)、`summary`(总公里数/总分钟/结束时间);
- `best_key` 取总分最低的算法作为默认展示。

### 8. 写回记忆(数据积累)
- 用到的地点写入 `db.remember_place`——下次"去银行"直接补坐标;
- 休息偏好 `save_prefs`;
- 历史计划 `save_plan`——前端历史记录/恢复功能的数据来源,也是以后做行为预测(ML 化)的原始数据。

## 其他 API

| 路由 | 作用 |
|---|---|
| `GET /` | 渲染前端模板,注入高德 JS Key |
| `GET /api/places?keyword=` | 查去过的地点(前端快捷提示) |
| `GET /api/plans` | 历史计划列表(最近 20 条) |
| `GET /api/plans/<id>` | 单个计划详情(恢复显示) |
| `DELETE /api/plans` | 清空历史计划 |
| `POST /api/geocode` | 定位"家",返回坐标 + 候选 |
| `GET /sw.js` | PWA Service Worker(挂根路径才能控制全站) |

## 关键设计决策

- **薄路由层**:业务逻辑不在路由里堆,算法/解析/地理各自成模块,便于单元测试(`test.py` 里大量直接测模块函数);
- **全链路降级**:没 Key、网络失败、解析失败,每一层都有兜底,唯一硬失败是"任务地点真的无法识别"(因为坐标是算法的前提);
- **任务上限 30 个**:防止路网矩阵请求过多(两两组合是 O(n²)),前端也做了一致校验;
- **地点选择两轮交互**:机器不替用户做主,歧义地点让用户挑,同时"常用"记忆排前面,减少操作成本。
