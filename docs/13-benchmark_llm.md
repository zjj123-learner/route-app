# benchmark_llm.py 详解 —— 规则 vs LLM 解析对比实验

## 这个文件为什么存在

LLM 解析器(llm_parser.py)花了大力气调 prompt + 后处理,到底值不值?这个脚本用 corpus.py 的 50 训练 + 15 泛化语料,把**规则解析和 LLM 解析放在同一把尺子上对比**,量化"LLM 相对规则的增益"。

## 实验设计

### 对照组固定

规则解析是**固定对照组,不随 LLM 调优而改动**(见 `benchmark_llm.py` 开头注释: "规则解析完全离线; LLM 解析需要配 Key。实验设计: 规则解析是固定对照组(不调优), 调优只针对 LLM 路径")。这样结论干净:LLM 好了就是 LLM 的功劳,不是"顺手把规则也改了"。

### `FIELDS` —— 逐字段打分

```python
FIELDS = ["day", "earliest", "latest", "fixed", "deadline", "priority", "duration", "place"]
```

不是简单的"整句对不对",而是**字段级**对比——"地点对了但时间错了"和"全对"是两种不同的失败,字段级才能定位问题出在哪。

### `absolute(entry)` —— 口径统一

语料里时间字段是"当天第几分钟",解析器输出是"绝对分钟(day×1440+分钟)",评测前把语料抬成绝对分钟,两边才能对等比较。

### `score_one(expected, got)` —— 单条打分

返回 `(是否全对, {字段: 对错})`,既看整句全对率,也看字段级对错。

### `run_rule(entries)` / `run_llm(entries)` —— 跑两路

规则:直接 `parse_line`,全离线;LLM:逐条调接口(需要 Key)。`--gen` 只跑泛化集,`--limit N` 只跑前 N 条调试。

## 用法

```bash
python benchmark_llm.py            # 有 Key:训练集 50 条全量对比
python benchmark_llm.py --gen      # 泛化集 15 条(测泛化能力)
python benchmark_llm.py --rule     # 只跑规则(没 Key 时默认)
python benchmark_llm.py --limit 10 # 调试
```

## 怎么读结果

- **训练集(50)**:规则全过是"应该的"(正则就是按语料写的);LLM 全对率反映"模型 + prompt + 后处理"对语料格式的拟合;
- **泛化集(15)**:这是**真正有价值**的数字——规则大概率惨败(它的词典里没有"菜鸟驿站/游泳馆/接娃"),LLM 若明显更好,就证明"LLM 的价值在泛化,不在背题"。

## 局限(如实说)

- 语料是作者手工编写的,规模小,存在对语料格式过拟合的风险;
- 泛化集 15 条样本量不足以支撑统计显著性;
- LLM 评测需要真金白银调 API,所以默认不开。

下一步方向:采集真实输入扩到几百条、做字段级错误分析(哪类表达 LLM 最常错)、以及"规则 vs few-shot vs 微调"三基线对比——后者就是把项目做成正经 NLP 信息抽取实验的起点。
